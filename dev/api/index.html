Discrete-time IBM

IndividualBasedPopulationDynamics.ibm_world — Function
ibm_world(survival, growth, fecundity, domain; rng, traits0, eviction=:reflect)

Build an Ark World of Size entities for an individual-based realization, with the vital rates, RNG, domain, and eviction policy stored as resources and one entity spawned per value in traits0.

source
IndividualBasedPopulationDynamics.ibm_step! — Function
ibm_step!(world)

Advance one discrete time step. Within a single Query (which locks the world) each individual's offspring and survival/growth are resolved against its current trait; structural changes (deaths, births) are buffered and applied after the query completes. The conditional mean reproduces the deterministic IPM kernel K = P + F.

source

ibm_run!(world, n_steps; save_traits=false) -> (; N, traits)

Run n_steps discrete steps in place. Returns the population-size trajectory N (length n_steps+1, including the initial size) and, if save_traits, the trait vectors at each saved time.

Continuous-time IBM (measure-valued PDMP)

IndividualBasedPopulationDynamics.CTVitalRates — Type

Per-individual continuous-time vital rates: deterministic growth flow(x), mortality(x) death rate, fecundity(x) birth rate, and recruit(rng) returning an offspring trait. (Non-parametric for Ark resource keying.)

source
IndividualBasedPopulationDynamics.ibm_world_ct — Function
ibm_world_ct(flow, mortality, fecundity, recruit, domain; rng, traits0, eviction=:reflect)

Build an Ark World for a continuous-time individual-based realization (a measure-valued PDMP): individuals flow deterministically by flow(x) and undergo death (rate mortality(x)) and birth (rate fecundity(x), offspring trait from recruit(rng)) jumps. This is the individual-level dual of a PSPM transport problem (flow=velocity, mortality=mortality, births=boundary/fecundity).

source
IndividualBasedPopulationDynamics.ibm_step_ct! — Function
ibm_step_ct!(world, dt)

Advance continuous time by dt with an operator split: over [t, t+dt] each individual produces Poisson(fecundity(x)·dt) offspring, dies with probability 1 - exp(-mortality(x)·dt), and otherwise flows to x + flow(x)·dt (Euler). Exact as dt → 0; the mean obeys the transport/​generator equation.

source

ibm_run_ct!(world, tspan; dt, saveat=dt, save_traits=false) -> (; t, N, traits)

Run the continuous-time IBM over tspan with step dt, recording population size (and optionally traits) every saveat.

Super-individuals

IndividualBasedPopulationDynamics.Weight — Type

Super-individual weight: the number of real individuals a particle represents.

source
IndividualBasedPopulationDynamics.ibm_world_super — Function
ibm_world_super(survival, growth, fecundity, domain; rng, traits0, weights0, eviction=:reflect)

Build an Ark World of weighted super-individuals (Size + Weight): each particle represents Weight.w real individuals at one trait. weights0 defaults to all-ones (the exact IBM). Demographic events use exact aggregate draws (Binomial survivors, Poisson offspring), so total-count statistics match the unweighted IBM while the entity count stays small.

source
IndividualBasedPopulationDynamics.ibm_step_super! — Function
ibm_step_super!(world)

One discrete step for weighted super-individuals. A particle (z, w) draws its aggregate offspring/survivor counts with Poisson(w · expected_offspring(z)) and Binomial(w, survival(z)), but each represented individual then gets an independent recruit/growth trait draw. This preserves the super-individual count-process statistics while restoring within-particle trait variance.

source

ibm_run_super!(world, n_steps; merge_domain=nothing) -> (; N, particles)

Stage structure (pure-jump finite-state IBM)

IndividualBasedPopulationDynamics.Stage — Type

Discrete stage of an individual (the individual-based analogue of a finite state). Multi-component individuals combine Stage with Size/Age.

source
IndividualBasedPopulationDynamics.StageVitalRates — Type

Per-stage continuous-time rates: Qtrans[s', s] = rate of an s-individual transitioning to s' (off-diagonal movement), death[s] mortality rate, and birth matrix birth[s', s] = rate an s-individual produces an offspring in stage s'. (Non-parametric for Ark resource keying.)

source
IndividualBasedPopulationDynamics.ibm_world_stage — Function
ibm_world_stage(Qtrans, death, birth; rng, stages0)

Build an Ark World of Stage individuals for a stage-structured continuous-time IBM — a pure-jump Markov process whose mean is the finite-state generator dn/dt = G·n (with G assembled from the transition/death/birth rates; birth is the offspring matrix birth[to, from]). One entity is spawned per entry of stages0.

source
IndividualBasedPopulationDynamics.ibm_step_stage! — Function
ibm_step_stage!(world, dt)

One operator-split step: each individual in stage s produces Poisson(birth[to, s]·dt) offspring in each stage to, and with probability 1 - exp(-R·dt) (R = total transition + death rate) undergoes one event — death, or a transition to s' with probability Qtrans[s', s] / R (an in-place stage change).

source

Run the stage-structured IBM over tspan with step dt, recording the per-stage counts every saveat.

SciML problem and integrator

An individual-based model as a SciML problem, so that solve, ensembles and simulation-based resilience metrics (recovery, basin_stability and the early-warning indicators of DynamicalResilience.jl) apply to it. The state is the population binned on the mesh (or counted by stage).

IndividualBasedPopulationDynamics.IBMProblem — Type
IBMProblem(rates, u0, tspan; domain=nothing, dt=1, seed=0, eviction=:reflect)

An individual-based population model as a SciML problem. rates chooses the model:

  • VitalRates(survival, growth, fecundity): the discrete-time size-structured IBM of ibm_world (one step per generation; dt must be 1);
  • CTVitalRates(flow, mortality, fecundity, recruit): the continuous-time IBM of ibm_world_ct, stepped with dt;
  • StageVitalRates(Qtrans, death, birth): the stage-structured IBM of ibm_world_stage, stepped with dt.

State. The state u is a Vector{Float64}: the number of individuals in each of the domain.n_meshpoints equal bins of domain ([lower, upper], as in trait_histogram) for size-structured models, or in each stage for stage models. u0 is such a vector of counts; individuals are created from it with traits uniform within their bin, using the run's random number generator, so a run is a function of u0 and seed only. Non-integer counts are rounded stochastically (to the floor or the ceiling, with probabilities that keep the expected count).

Randomness. Each run uses Random.Xoshiro(seed); reinit! restarts it, so reinitialising replays a run exactly.

Changing the state. Assigning integ.u (then derivative_discontinuity!(integ, true)) or calling set_u!(integ, u) changes the population to the new counts before the next step: in a bin (or stage) that must lose individuals, that many are removed uniformly at random among those in it; in one that must gain, new individuals are added with traits uniform in the bin. So a perturbation acts at the resolution of the mesh.

IndividualBasedPopulationDynamics.IBMStepping — Type
IBMStepping()

The algorithm of an IBMProblem: advance the individual-based world one step at a time with the package's own stepping functions (ibm_step!, ibm_step_ct! or ibm_step_stage!).

source
IndividualBasedPopulationDynamics.IBMIntegrator — Type
IBMIntegrator

The stepping state of an IBMProblem, created by init(prob, IBMStepping(); ...), with the interface of a SciML integrator:

  • integ.u: the binned (or staged) counts, a Vector{Float64}; integ.t: the time; integ.world: the Ark world of individuals.
  • step!(integ) (one step of dt), step!(integ, n) (n steps), step!(integ, dt, stop_at_tdt) (until the time has advanced by at least dt, or exactly dt, which must then be a whole number of steps), solve!(integ), reinit!(integ), set_u!(integ, u), terminate!(integ), check_error(integ).
  • Changing integ.u in place takes effect before the next step once derivative_discontinuity!(integ, true) (or u_modified!) is called.
